## 1. Executive Summary

This specification establishes the architecture for adding **PHP (8.1+)** as the 5th native client ecosystem to `pak-geodata` alongside TypeScript (NPM), Python (PyPI), Go (`packages/go`), and Dart/Flutter (`pub.dev`), while resolving the GitHub Actions release workflow duplication race condition.

### Key Tenets
1. **Single Source of Truth**: All master data resides in `data/` (7 provinces, 79 cities, 3,953 areas). The PHP package never stores or accepts manual edits.
2. **Zero External Runtime Dependencies**: Pure PHP 8.1+ standard library only (`math`, `mbstring`, standard array functions). Zero external packages required for production runtime.
3. **OPcache Native Array Compilation**: Compiled via `scripts/codegen/php.ts` into native PHP return arrays (`src/Data/Areas.php`, `Cities.php`, `Provinces.php`) to leverage Zend OPcache shared memory bytecode for zero JSON parsing latency on web requests (Laravel, Symfony, WordPress).
4. **Strict Dataset Parity**: Two-tier verification gate asserting identical counts (7 provinces, 79 cities, 3,953 areas) across all 6 targets.
5. **Cross-Language Test Parity**: Shared golden test vectors (`tests/parity/golden_vectors.json`) executed against the PHP package via PHPUnit.
6. **Clean Release Pipeline**: Streamlined `.github/workflows/release.yml` triggering solely on `push: tags: ['v*']` to prevent concurrent duplicate releases.

## 4. Code Generation (`scripts/codegen/php.ts`)

A dedicated code generator `scripts/codegen/php.ts` will transform master JSON data into PHP return arrays:

```typescript
// scripts/codegen/php.ts
export function generatePhpProvinces(provinces: RawProvince[]): string;
export function generatePhpCities(cities: RawCity[]): string;
export function generatePhpAreas(areas: RawArea[]): string;
```

Output format for `packages/php/src/Data/Areas.php`:
```php
<?php

declare(strict_types=1);

namespace PakGeoData\Data;

return [
    [
        'id' => 'lahore-dha-phase-5',
        'cityId' => 'lahore',
        'provinceId' => 'punjab',
        'name' => 'DHA Phase 5',
        'urduName' => 'ڈی ایچ اے فیز 5',
        'postalCode' => '54792',
        'coordinates' => ['lat' => 31.4697, 'lng' => 74.4133],
        'aliases' => ['dha 5', 'dha phase v', 'defence phase 5'],
        'type' => 'housing_scheme',
        'verified' => true,
        'sources' => ['survey', 'curated'],
    ],
    // ... all 3,953 areas
];
```

Strings are formatted with proper PHP escaping, single quotes, and direct UTF-8 preservation for Urdu characters (`ڈی ایچ اے`, `گلبرگ`, etc.).

## 5. Public API Specification (`PakGeoData\PakGeoData`)

### Methods
- `PakGeoData::getAllProvinces(): array<Province>`
- `PakGeoData::getProvinceById(string $id): ?Province`
- `PakGeoData::getAllCities(): array<City>`
- `PakGeoData::getCityById(string $id): ?City`
- `PakGeoData::getCitiesByProvince(string $provinceId): array<City>`
- `PakGeoData::getAllAreas(): array<Area>`
- `PakGeoData::getAreasByCity(string $cityId): array<Area>`
- `PakGeoData::getAreaById(string $id): ?Area`
- `PakGeoData::findAreaByPostalCode(string|int $postalCode): ?Area`
- `PakGeoData::findAreasByPostalCode(string|int $postalCode): array<Area>`
- `PakGeoData::haversineDistanceKm(Coordinates $c1, Coordinates $c2): float`
- `PakGeoData::getNearestArea(Coordinates $coords, ?string $cityId = null, ?float $maxRadiusKm = null, ?string $provinceId = null): ?NearestAreaResult`
- `PakGeoData::searchAreas(string $query, ?string $cityId = null, int $limit = 20, ?string $provinceId = null): array<SearchResult>`
- `PakGeoData::normalizeUrduText(string $text): string`

### Memory & Performance Strategy
- Lookups initialize lazily on first access.
- Static associative maps are built once per process lifecycle:
  - `$areasById`: `array<string, Area>`
  - `$areasByCity`: `array<string, array<Area>>`
  - `$areasByPostalCode`: `array<string, array<Area>>`
  - `$citiesById`: `array<string, City>`
  - `$provincesById`: `array<string, Province>`
- OPcache retains the data arrays in shared memory, allowing near-instant execution across concurrent web requests.

## 6. Spatial Reverse Geocoding & Urdu NLP

### 1. Haversine Formula (`Geo::haversineDistanceKm`)
- Spherical Earth radius $R = 6371.0088\text{ km}$.
- Formula:
  $$\Delta\text{lat} = \text{lat}_2 - \text{lat}_1, \quad \Delta\text{lng} = \text{lng}_2 - \text{lng}_1$$
  $$a = \sin^2\left(\frac{\Delta\text{lat}}{2}\right) + \cos(\text{lat}_1)\cos(\text{lat}_2)\sin^2\left(\frac{\Delta\text{lng}}{2}\right)$$
  $$a = \max(0.0, \min(1.0, a)) \quad \text{// Clamp antipodal float precision}$$
  $$c = 2 \cdot \text{atan2}(\sqrt{a}, \sqrt{1 - a})$$
  $$d = R \cdot c$$

### 2. Urdu Normalization & Search Ranking (`Search::searchAreas`)
1. Diacritic stripping: Strip Arabic/Urdu Harakat/Tashkeel (`\x{064B}` to `\x{065F}`, `\x{0670}`).
2. Letter unification:
   - Alef: `[آأإٱ]` $\rightarrow$ `ا`
   - Yeh: `[يىئے]` $\rightarrow$ `ی`
   - Kaf: `[ك]` $\rightarrow$ `ک`
   - Heh: `[ةھ]` $\rightarrow$ `ہ`
3. Numeral conversion: Convert Eastern Arabic numerals `[۰-۹]` and `[٠-٩]` to Western `[0-9]`.
4. Ranking tiers:
   - Exact match ($1000$)
   - Prefix match ($700$)
   - Urdu script match ($650$)
   - Colloquial alias match ($600$)
   - Token intersection ($300$)
   - Fuzzy Levenshtein match ($150$)

- `scripts/verify.ts` and `scripts/build.ts` Step 5 are updated to verify **6 targets**:
  1. Master JSON files in `data/`

### Monorepo Scripts (`package.json`)

## 8. CI/CD & Release Workflow Streamlining

### 1. Continuous Integration (`.github/workflows/ci.yml`)
- Add PHP setup step using `shivammathur/setup-php@v2` with `php-version: '8.2'`.
- Run `composer install --prefer-dist --no-interaction` in `packages/php`.
- Execute `npm run test:php`.

### 2. Release Workflow (`.github/workflows/release.yml`)
- **Fix Duplicate Release Bug**:
  Remove `release: types: [published]` from `on:`.
  Keep exclusively:
  ```yaml
  on:
    push:
      tags:
        - 'v*'
    workflow_dispatch:
  ```
  Since `pub.dev` OIDC requires `push` events, and publishing a GitHub Release pushes the tag `v*`, this eliminates the duplicate run race condition while ensuring all registries (NPM, PyPI, Go tag, Pub.dev, Packagist) trigger cleanly once.
- **Packagist Integration**:
  Packagist is Git-tag driven. When tag `v*` is pushed to GitHub, Packagist's GitHub webhook automatically registers the new version for `sohaibbinmohsin/pak-geodata`.
